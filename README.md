# Anatomy Studio · 人体结构学智能刷题与错题管理系统

面向在校医学专业学生的《人体结构学》（系统解剖学 + 组织学与胚胎学）本地刷题工具：
把 **1917 道课程习题**、**289 道解剖图谱 / 组胚切片** 与 **结构化课堂笔记** 绑定在一起，
配合大模型提供靶向破题与干扰项排雷，并把错题按遗忘风险排序，直接给出考前该看哪几道。

题库来自课程配套练习，答案逐题核验；笔记来自按照课程进度整理的 Obsidian 知识库。
所有数据保存在本机，除了你自己配置的大模型接口，不上传任何内容（建议在设置中配置个人大模型 API Key，以解锁实时靶向破题与选项矩阵重析；未配置时将展示内置的笔记推导与已有解析缓存）。

## 项目概述 (Overview)

《人体结构学》的备考困难不在“题少”，而在三个具体的地方：

| 痛点 | 表现 | 本项目的处理 |
| --- | --- | --- |
| **有题无解析** | 课程练习只给答案字母，不讲为什么；错题下次还是错 | 每道题都绑定笔记原文段落；配置大模型后生成题眼、干扰项逐个排雷、避坑总结 |
| **易混概念缺横向对比** | 「上斜肌 / 下斜肌 / 上直肌」的神经支配和转向，「浆膜 / 黏膜 / 纤维膜」的层次，光靠单题记忆必然混淆 | 选项级概念对比矩阵：A–E 每个选项单独给出标准医学定义与本题判别结论（要开靶向精析才能看到） |
| **错题缺复习优先级** | 错题本只按时间堆，不清楚先补哪个；反复做对的题还在占时间 | 按 `权重 = 错误次数 × 2 − 连对次数 + 收藏加成` 排序，连对 3 次自动移出 |

题库规模与覆盖：

- 单选 1578 道，多选 339 道；排除 163 道依赖三维模型的题型（当前版本不呈现）
- 1917 道全部带笔记正文溯源，1830 道带选项级定义，289 道带图谱 / 切片（共 469 张次，196 个实体文件）
- 章节按课程原始体系分为 6 篇 17 章，支持「篇 → 章」两级多选筛选

## 核心功能 (Core Features)

### 1. 双轨制解析系统

作答后打开解析抽屉，左右两栏并行，可单独切换：

- **📚 笔记原文溯源**：从知识库中定位到这道题对应的小节，展示原始 Markdown 段落、双链结构、解剖图谱与组胚切片（点击全屏灯箱），并可用 `obsidian://` 直接跳回 Obsidian 对应标题。
- **🎯 靶向破题精析**：把【题干 + 各选项 + 标准答案 + 笔记原文】一起交给大模型，输出三段结构化分析——**破题眼**（一句话点明考查的核心特征）、**干扰项排雷**（B/C/D 各自错在哪个概念的偷换上，你选错的那项会置顶并标红）、**避坑锚点**（对比口诀或易错提醒）。

未配置 API Key 时不会报错：解析退化为「本地推导」，直接用笔记原文里的定义说明为什么选它，界面上标注数据来源。
生成的解析会写回本地缓存，同一道题第二次打开是零延迟。

### 2. 选项级概念对比矩阵

针对 A–E 全部选项生成独立的标准医学定义剖析，例如：

> **A. 上斜肌**　属眼球外肌，由滑车神经（Ⅳ）支配（非动眼神经），收缩时使瞳孔转向外下方。故 A 为本题正确答案。
> **B. 下斜肌**　由动眼神经（Ⅲ）下支支配，收缩时使瞳孔转向外上方。

用于横向对比易混淆的解剖结构、神经支配、走行毗邻，或细胞超微结构与染色性质。
矩阵由大模型按人卫版教材口径生成后**写回本地题库文件**，下次秒开；对已有结果可随时「AI 重新精析」覆盖。

### 3. 审题防坑标注

自动识别题干中的三类陷阱并在阅读时高亮：

- **否定词**（「不属于」「除外」「错误的是」）—— 158 道题命中
- **解剖学方位词**（「内上方」「前外侧」等，这些词本身就是考点）
- **观察尺度词**（「光镜下」「电镜下」「HE 染色」—— 组胚题里尺度错位是最常见的失分点）

可设置为「答题前始终显示」「仅作答后显示」或关闭。

### 4. 薄弱点量化与考前急救队列

- 自动记录每道题的作答次数、错误次数、连对次数、最近一次作答时间
- **急救队列权重**：`错误次数 × 2 − 连对次数 + (收藏 ? 1.5 : 0)`，连对达到阈值（默认 3 次）自动移出
- 分析页给出：覆盖率、正确率、按篇/章的掌握度热力图、错题的概念分布、每日练习量
- 首页「待抢救」数量即急救队列长度，点进去直接开练

### 5. 云端笔记与题库热同步

维护者会持续往仓库推送新的章节笔记映射、新增图谱切片与解析缓存。软件右上角的「同步题库」胶囊：

- 启动时静默检查一次远端版本清单 `data/version.json`（拿不到才退回 GitHub API）
- 有更新时亮起提示点，悬浮可看到题库版本与本次更新说明
- 点击即增量下载：题库文件 + 本次新增的图谱切片（已有的不重复下载）
- **不覆盖**你的 `user_progress.json`（错题与做题记录）与 `user_config.json`（个人 API Key）；
  本地已用 API 生成的靶向解析，即使远端为空也会保留
- 校园网直连 `raw.githubusercontent.com` 失败时自动依次尝试 `mirror.ghproxy.com`、`ghp.ci` 镜像
- 客户端本身有大版本更新时，提供跳转 Releases 的入口

### 5.1 更新提醒是主动弹出来的

仓库里维护着一份 `data/version.json` 版本清单，记录客户端版本、题库版本与更新说明：

```json
{
  "app_version": "2.1.0",
  "app_release_notes": "首个正式版本发布：支持双轨解析、选项矩阵与考前急救队列。",
  "release_url": "https://github.com/CBYYY1/Anatomy-Studio/releases",
  "bank_version": "2026.11.17.2",
  "bank_updated_at": "2026-11-17 21:23:44",
  "bank_changelog": "更新章节笔记映射与靶向解析缓存",
  "stats": { "total_questions": 1917, "matched_notes": 163, "media_count": 196 }
}
```

- 只读这一个文件（几百字节）就能判断有没有更新，不用等 GitHub API，
  也就不会撞上未登录每小时 60 次的限流；`api.github.com` 只在清单拿不到时兜底
- 启动检测到题库或客户端有新版本时，直接在应用内弹出提示，写清版本号与更新内容，
  可选「立即同步题库 / 去 Releases 下载 / 这个版本不再提示 / 稍后再说」
- 同一版本只提醒一次：点过「不再提示」或成功同步后，已读版本记在浏览器本地，刷新不再打扰
- 觉得吵可以在 设置 → 数据与备份 → 云端同步 里关掉「检测到更新时主动弹窗」或「启动时自动检查」
- 重建题库时 `build_question_bank.py` 会自动刷新 `data/version.json`（题库版本按日期自增，
  人工写的发版说明与更新日志会被保留），随 Git 提交即可让所有用户收到提醒

仓库地址默认已绑定本仓库 `CBYYY1/Anatomy-Studio`，开箱即可直接同步；
若自行 Fork 维护，可在 设置 → 数据与备份 → 云端同步 → 仓库地址 里改成 `owner/repo`（也可改 `config.py` 里的 `GITHUB_REPO` 作为默认值），
点「检查更新」确认能读到 `data/version.json` 的最新提交即可。

### 6. 其他

- 三套主题（深色 / 纯黑 OLED / 浅色）、三档题干字号、减弱动效开关
- 键盘作答：`A`–`E` 选项、`Enter` 提交、`←/→` 上下题、`Ctrl + ,` 打开设置
- 自动答题进度保存：关掉浏览器再打开，回到离开时那道题

## 快速开始 (Quick Start)

### 免安装便携版（推荐）

到仓库右侧 **Releases** 下载最新的 `AnatomyStudio_Portable.zip`（约 47 MB），解压到任意目录，双击 **`启动 Anatomy Studio.bat`**。

- 浏览器会自动打开 `http://127.0.0.1:18080/`（端口被占用会自动顺延，以窗口里打印的地址为准）
- 关闭那个黑色命令行窗口即停止服务
- **不依赖** Python / Node.js / Obsidian：内置笔记解析开箱可用
- 如需实时调用大模型生成深度精析：点右上角齿轮（或按 `Ctrl + ,`）→ **AI 引擎** → 选择服务商（DeepSeek / 阿里云百炼 / 硅基流动 / 火山方舟 / Kimi / 智谱 / 本地 Ollama / 自定义 OpenAI 兼容）→ 填入自己的 API Key → 点「测试连接」
- 模型名不是写死的：可以直接手填任意模型 ID，也可以点「同步」拉取该平台当前在线的全部模型

软件会在 exe 同级的 `data/` 目录里保存你的进度与配置，整个文件夹可以随意拷到 U 盘或另一台电脑继续用。

### 源码运行

需要 **Python 3.10+** 与 **Node.js 18+**。

```powershell
git clone <repo-url>
cd anatomy-studio

# 1) 后端依赖
pip install -r requirements.txt

# 2) 前端构建（只在这一步需要 Node）
cd web
npm install
npm run build
cd ..

# 3) 启动（自动打开浏览器）
python server.py
```

默认监听 `http://127.0.0.1:8788/`。
首次启动会从 `data/user_config.example.json` 与 `data/user_progress.example.json` 生成你自己的配置与空进度，开箱即用。

`config.json` 只保留服务端监听参数，界面里的设置存在 `data/user_config.json`（已加入 `.gitignore`）：

```json
{ "host": "127.0.0.1", "port": 8788 }
```

### 挂载自己的 Obsidian 笔记库

题库里的笔记原文来自一个 Obsidian 库，默认以「内置静态解析」模式运行（读题库内嵌的段落与图片）。
如果你有自己的库，想按自己的笔记重新生成关联：

1. 设置 → **知识库** → 切到「本地 Obsidian 联动」，填入 vault 路径，点「验证路径」
2. 在 `build_question_bank.py` 顶部改 `VAULT` 指向你的库（结构参照 `docs/MAINTAINER.md`）
3. 运行重建：

```powershell
python build_question_bank.py        # 重新匹配 1917 道题与你的笔记
python bundle_media.py               # 把题库引用到的图片抽到 data/media/
```

匹配算法用 BM25 在笔记正文上做二元组检索，再用「答案选项的稀有 2-gram 是否落在选中小节」做过质量评估；
具体设计与调参过程见 `docs/MAINTAINER.md`。

### 大模型接口配置的两种方式

界面里填最省事。也支持环境变量与 `.env`（优先级：**界面 > 环境变量 > `.env`**）：

```powershell
copy .env.example .env
# 编辑 .env，填 DEEPSEEK_API_KEY / DEEPSEEK_BASE_URL / DEEPSEEK_MODEL
```

没有 Key 也能完整使用：双轨解析退化为本地笔记推导，其余功能不受影响。

### 数据在哪、怎么备份

| 文件 | 内容 | 是否入库 |
| --- | --- | --- |
| `data/questions.json` | 题库与笔记映射（约 7 MB） | ✅ 随仓库分发 |
| `data/media/` | 图谱与组胚切片（196 张，30 MB） | ✅ 随仓库分发 |
| `data/user_config.json` | 你的 API Key 与界面偏好 | ❌ 已 `.gitignore` |
| `data/user_progress.json` | 错题、收藏、作答历史 | ❌ 已 `.gitignore` |

换电脑或升级前，设置 → **数据与备份** → 导出 `.json` 存一份；回来导入即可。
云端同步与题库热更新都不会碰这两个文件。

## 常见问题

**Q：必须连校园网吗？**
不需要。刷题、解析、错题统计、图谱全部离线可用。只有点「同步题库」（从 GitHub 拉更新）和调用大模型 API 时需要联网。

**Q：题库和答案哪来的？**
整理自课程配套练习与常考基础习题，结合教材逐题核验；解析部分统一由笔记原文 + 大模型生成，不是官方答案。

**Q：用了大模型，会不会把题目发到不该去的地方？**
只有你主动触发生成解析时，才会把【该题题干、选项、答案】与【对应的笔记段落】发给你自己配置的服务商。进度、错题、笔记库本身不会外传。

**Q：笔记里某道题匹配得不准怎么办？**
对已知的两类情况（纯方位描述题、主题词无区分度的「总论」题），系统会退到专用通道处理；仍有个别题目受限于教材本身没有独立小节。
这类题可以直接在解析抽屉里点「AI 重新精析」，用模型自身的教材知识覆盖。

**Q：能改成我学校的题库吗？**
可以。`data/questions.json` 是一个结构化数组，字段见 `docs/MAINTAINER.md`；导入后在设置里点「题库热更新」选择文件即可，已有的错题计数与收藏会保留。

## 目录结构

```
studio/
├── server.py                FastAPI 后端：题库 / 进度 / 笔记 / 媒体 / 设置 / 云同步
├── config.py                配置读写与迁移（data/user_config.json）
├── analysis.py              大模型调用、Prompt 组装、解析缓存、本地兜底推导
├── updater.py               版本清单检测、主动更新提示与题库热同步
├── build_question_bank.py   Obsidian 笔记 ↔ 题库匹配，生成 data/questions.json 与 data/version.json
├── bundle_media.py          把题库引用的图片抽到 data/media/
├── batch_analyze.py         按章节批量预生成解析（可选）
├── build_portable.py        打包免安装便携版
├── data/                    题库、媒体、个人配置与进度
│   └── version.json         版本清单：客户端/题库版本与更新说明，用于应用内更新提示
├── web/                     前端（React + Vite + Tailwind）
│   └── src/
│       ├── views/           概览 / 练习 / 分析 / 题库 / 设置
│       ├── components/      解析抽屉、章节选择器、同步胶囊、图表
│       └── lib/             Markdown 与公式处理
└── docs/MAINTAINER.md       维护者文档：匹配算法评测、踩坑记录、打包流程
```
